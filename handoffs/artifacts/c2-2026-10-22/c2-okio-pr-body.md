An audit identified the gaps this work fills. These changes add tests unless a new test exposes a real defect. Here the concurrent SimpleFileSystemServiceServer publish test exposed `failed to create directory: .../.sfsemb-staging` when two callers created the same directory through Okio's NIO adapter, so this PR fixes that upstream implementation as well.

The adapter checked whether the directory existed before creating it and used that earlier answer after an IOException. Two callers could both see absence, then one caller failed after the other created the directory; an earlier positive directory check could also hide a later error or a file replacing the directory. The adapter now accepts only FileAlreadyExistsException when mustCreate is false and fresh metadata identifies a directory; the other errors retain their path and cause. The implementation fix is https://github.com/CodexCoder21Organization/okio/commit/348a832e9eb1ea564b27ff2a53c0dd5bdcea9898; the unchanged downstream fail-first test is https://github.com/CodexCoder21Organization/SimpleFileSystemServiceServer/commit/0f7a72d.

Tests use the public asOkioFileSystem/createDirectory API over real Jimfs storage. A forwarding NIO filesystem orders public path resolution so both absent reads finish before either create starts. The native Gradle layout has one scenario per test file; its compatible-artifact runner executes the same scenarios with a 128 MiB heap.

- ConcurrentNioDirectoryCreationTest: 32 rounds with two callers, both mustCreate modes, retained child contents, and existing/competing file targets.
- ExistingNioDirectoryFailureTest: an existing directory does not hide an unrelated creation error.
- ReplacedNioDirectoryCreationTest: a directory replaced by a file does not count as successful directory creation.
